How an AI agent works: one loop inside a harness

How AI agents work: one loop inside a harness. Want to really understand AI agents? Don't just read about them. Build a small one.

First, here's what's going on inside, in plain words.

Most agents run the same loop (it has a name: ReAct): think, act, look at the result, go again.

Let's walk one request through it.
You type: "Move my 3pm with Omar to Thursday."

𝟭/ 𝗖𝗼𝗻𝘁𝗲𝘅𝘁
→ The model can't see your calendar. It only sees what the harness hands it.
→ Your message, its instructions, the tools it may use, anything pulled from memory.
→ If nothing says which Omar, it has to guess or ask.

𝟮/ 𝗗𝗲𝗰𝗶𝗱𝗲
→ It reads all of that and picks one next step: reply now, or use a tool.
→ Here it needs the calendar.
→ The model only writes text. It can't move a meeting on its own.

𝟯/ 𝗔𝗰𝘁
→ It writes a tool call: "find today's 15:00 event with Omar".
→ The harness runs that call against your calendar.
→ Get the date wrong in the call and it finds nothing.

𝟰/ 𝗢𝗯𝘀𝗲𝗿𝘃𝗲
→ The result comes back: "1 event found", or "no match".
→ The harness adds it to the context and asks the model again.
→ Now it decides: move it, ask you, or stop.

That loop repeats until the model says it's done or a limit stops it.
With no step cap, it can retry the same failing call again and again, and you pay for every one.

𝟱/ 𝗖𝗵𝗲𝗰𝗸𝘀 𝗮𝗿𝗼𝘂𝗻𝗱 𝘁𝗵𝗲 𝗹𝗼𝗼𝗽
→ Permissions: what the agent may touch
→ Guardrails: what it must never do
→ Evals: whether its results are actually right
→ Human sign-off: who approves the risky actions
→ Traces and logs: what it did, and why

So understanding an agent means seeing what it was given, what it called, what came back, and who checked it.

Once you can see that, you can debug it and make it better.

Next step: build one. You'll learn more in an afternoon than in a month of reading.

How an AI agent works: one loop inside a harness

How AI agents actually work: a model inside a harness runs one loop (build context, decide, act with tools, observe, repeat) until it answers or a step cap stops it.
Free guide (build your first small agent with Claude Code): https://withhammad.com/resources/how-ai-agents-work

1. Trigger: you, an event, a timer or another agent starts it
2. Build context: instructions, tool list, chat so far, recalled memory, earlier tool results
3. Model decides: answer now, or call a tool
4. Act: the harness runs the tool (search, code, files, APIs, MCP servers, sub-agents)
5. Observe: the result goes back into the context and the loop runs again
Around it all: memory, guardrails, permissions, human sign-off, observability and evals. The model only writes text; the harness does the rest.
Set a step cap: without one, a failing call can repeat and every try costs money.

Sources: ReAct (Yao et al., 2022) https://arxiv.org/abs/2210.03629 and Anthropic, Building effective agents https://www.anthropic.com/engineering/building-effective-agents

Harness engineering: the layer that makes an AI agent reliable

Harness engineering: why AI agents fail in real work even when the model is fine.

When an agent breaks, people blame the model. Often the system around it is the problem.

Free guide, a checklist for each layer: https://withhammad.com/resources/harness-engineering

Everyone chases smarter agents:
A bigger model.
A better prompt.
More context.

The harness is everything around the model that keeps the agent dependable.

The model suggests what to do.
The harness decides how, and whether, it happens.

1/ Context Builder
→ The docs and data that matter
→ What's already been said and done
→ Where the task stands right now
Skip this and the model fills the gaps with guesses.

2/ The Model
It reasons, picks a tool, suggests an action.
It can also make things up, misread an instruction or loop on the same step.
A strong model helps. It doesn't make the result safe.

3/ Permission Check
→ May it read this data?
→ May it change this record?
→ Does a human need to sign off first?
That call belongs to your system, not the model.

4/ Tools & Runtime
APIs. Databases. CRMs. MCP servers.
Give each tool only the access the task needs. Then one wrong decision stays a small one.

5/ Verification
→ Did the payment really go through?
→ Is the right record updated?
→ Do the tests pass?
The model can say it worked. Your system has to show it.

6/ Observability & Feedback
Log every tool call. Record the errors. Count the retries.
Feed what you learn back into the system.
A failure you can see is a failure you can fix.

The short version: the model comes up with options. The harness turns them into actions, inside clear rules, and checks the result instead of trusting the reply.

That's the gap between a good demo and an AI product people can rely on.
